# brainstorming

透過結構化對話，在撰寫任何程式碼之前，將粗略想法轉化為完整設計。

## 概述

此技能透過結構化腦力激盪，幫助您思考功能、系統設計和產品決策。此流程能浮現隱藏的假設、探索替代方案，並產出清晰的設計文件。

## 流程

```
理解 ──► 探索 ──► 設計 ──► 記錄
(什麼/為什麼) (方法) (決策) (設計文件)
```

每個階段都建立在前一個的基礎上，不可跳過。

## 核心原則

| 原則 | 理由 |
|-----------|-----------|
| 一次一個問題 | 降低認知負擔，挖掘更深層的洞見 |
| 優先選擇題 | 加快對齊速度，暴露隱藏假設 |
| YAGNI | 防止過度工程；簡單即速度 |
| 探索替代方案 | 避免錨定於第一個想法 |
| 漸進式驗證 | 早期發現誤解，建立信心 |
| 提出建議，不只列選項 | 有觀點的指導比中立比較更有用 |

## 四個階段

### 1. 理解
一次一個問題，建立共同的心智模型：
- 誰使用這個？解決什麼問題？
- 存在哪些限制？
- 「完成」是什麼樣子？

### 2. 探索
以 2-3 個方法描繪解決方案空間：
- 列出每種方法的優缺點
- 以建議作為開頭
- 嚴格應用 YAGNI

### 3. 設計
以具體細節充實選定的方法：
- 資料模型和關鍵結構
- 核心流程和演算法
- 整合點和邊緣案例

### 4. 記錄
以文件形式為團隊記錄設計：
- 問題陳述
- 決策與選定方法
- 考慮過的替代方案
- 具體設計細節

## 適用時機

- 開始新功能或專案
- 重新思考系統架構
- 評估多種方法
- 在撰寫任何實作程式碼之前

## 後續步驟

腦力激盪後，繼續使用：
- **spec-kit**：將設計正式化為結構化規格
- **diagram-gen**：視覺化架構、資料流或元件關係
- **team-tasks**：協調多團隊工作流程的平行 agent 執行
