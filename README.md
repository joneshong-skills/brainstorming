# Brainstorming -- Collaborative Ideation Through Structured Dialogue

Turn rough ideas into fully formed designs BEFORE any code is written. Guide through a structured conversation that surfaces assumptions, explores trade-offs, and converges on a clear design.

## Overview

This skill helps you think through features, system designs, and product decisions through structured brainstorming. Rather than jumping straight to implementation, this workflow surfaces hidden assumptions, explores alternatives, and produces a clear design document.

## The Process

```
Understanding ──► Exploring ──► Designing ──► Documenting
  (what/why)    (approaches)   (decisions)    (design doc)
```

Each phase builds on the previous. Never skip ahead.

## Key Principles

| Principle | Rationale |
|-----------|-----------|
| One question at a time | Reduces cognitive load, surfaces deeper insights |
| Multiple choice preferred | Faster alignment, exposes hidden assumptions |
| YAGNI | Prevents over-engineering; simplicity enables speed |
| Explore alternatives | Avoids anchoring on the first idea |
| Incremental validation | Catches misunderstandings early, builds confidence |
| Recommend, don't just list | Opinionated guidance is more useful than neutral comparison |

## Four Phases

### 1. Understanding
Build a shared mental model by asking clarifying questions one at a time:
- Who uses this and what problem does it solve?
- What constraints exist?
- What does "done" look like?

### 2. Exploring
Map the solution space with 2-3 approaches:
- Propose each with pros/cons
- Lead with a recommendation
- Ruthlessly apply YAGNI

### 3. Designing
Flesh out the chosen approach with concrete details:
- Data models and key structures
- Core flows and algorithms
- Integration points and edge cases

### 4. Documenting
Capture the design in a document for the team:
- Problem statement
- Decision and chosen approach
- Alternatives considered
- Concrete design details

## When to Use This

- Starting a new feature or project
- Rethinking system architecture
- Evaluating multiple approaches
- Before writing any implementation code
